# Crop Yield Prediction Using LSTM

Season-ahead crop yield forecasting with a stacked LSTM (TensorFlow/Keras), benchmarked against
Linear Regression, Random Forest, XGBoost, a simple RNN and a GRU, and served through a Flask web app.
This is the working project behind the case study *Crop Yield Prediction Using LSTM*.

## Important: the bundled data is synthetic

`data/crop_yield.csv` is generated by `data/generate_synthetic.py` so the pipeline runs end to end.
It is **not real farm data**. Any metrics you get on it describe the generator, not real crops.
For your report, replace it with real district-level data (see "Using real data") and re-train.

## Quick start

```bash
python -m venv .venv && source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python data/generate_synthetic.py                         # optional: (re)create demo data
python -m src.train --epochs 5                            # quick smoke test
python -m src.train                                       # full training (early stopping)
python -m app.app                                         # open http://127.0.0.1:5000
python -m pytest -q                                       # unit tests (no TensorFlow needed)
```

Training writes to `models/` (model, scalers, metadata) and `outputs/`
(`metrics_table.csv`, `test_predictions.csv`, `fig_rmse_by_model.png`, `fig_loss_curve.png`,
`fig_actual_vs_pred.png`). Copy the numbers into Table 5.2 and the figures into Figures 5.1 / 5.2 of the report.

## How it works

| Step | File | What happens |
|---|---|---|
| Data | `data/crop_yield.csv` | one row per district-crop-year-**month** (12 rows per season) |
| Pre-processing | `src/preprocess.py` | interpolation of short gaps, 12-step sequences of shape (T, F), previous-season yield as a feature, one-hot crop and district |
| Split | `src/preprocess.py` | **chronological** by year: 70% train, 15% validation, 15% test |
| Scaling | `src/preprocess.py` | Min-Max scalers fitted on the training set only (no leakage), saved for inference |
| Model | `src/models.py` | LSTM(64, return seq) → Dropout(0.2) → LSTM(32) → Dropout(0.2) → Dense(16, ReLU) → Dense(1) |
| Training | `src/train.py` | Adam, MSE, early stopping, LR reduction; baselines trained on identical splits |
| Metrics | `src/metrics.py` | RMSE, MAE, MAPE, R² on original units (t/ha) |
| Serving | `app/` | Flask API (`/api/options`, `/api/history`, `/api/predict`) + browser UI |

The web UI lets you pick district, crop and season, optionally apply a rainfall / temperature
what-if, and shows the predicted yield with a ± test-RMSE band, the five-season average,
the yield history and the monthly weather the model used.

## Using real data

Provide `data/crop_yield.csv` with these columns (one row per month, 12 rows per district-crop-year):

`district, crop, year, month, rainfall, tmax, tmin, humidity, fertiliser, irrigated_pct, yield`

- `yield` is tonnes/hectare for the season (the same value on all 12 rows); `fertiliser` and
  `irrigated_pct` are season-level (also repeated).
- Suggested sources: crop area/production from data.gov.in (yield = production / area) and monthly
  weather from NASA POWER, joined on district and year.
- Need more years per district than the demo? Real series are usually short: keep the model small,
  keep the chronological split, and report results for several random seeds.

## Honest limitations

- The TensorFlow training code was written to the Keras API but could not be executed in the
  environment where it was authored (no TensorFlow available). Everything else (data pipeline,
  split, scaling, metrics, inference logic, Flask API) is covered by `tests/`, which use a small
  fake model in place of Keras. Run `python -m src.train --epochs 5` first; if anything in the
  Keras layer needs adjusting for your TensorFlow version, it will show up immediately.
- Predictions are point estimates; the ± band is the global test RMSE, not a calibrated interval.
- Not a substitute for official crop estimates or local agronomic advice.
